# Level design

The level format is in Game design, in `CLAUDE.md`. This file holds its details and reasons, and the alternatives rejected.

- Example, a home alarm. Statement: the alarm goes off if the motion, window and door sensors are all on; or if the motion and window sensors are on but the door sensor is off; or if the motion sensor is on but the window sensor is off. Starting formula: `1 = (2 & 3 & 4) | (2 & 3 & ~4) | (2 & ~3)`. Sentences: "Alarm on", "Motion sensor on", "Window sensor on", "Door sensor on". Solution: `1 = 2`.
- Propositions are numbers in the formulas, and their sentences come in a list. Each sentence is written once, so a typo cannot silently create another proposition; formulas stay short and easy to check, even with long sentences or with statements whose conditions come from context; and the analyzer reads numbers instead of text with spaces. The list holds only the sentences, in order, since the position gives the number, and the notation derives each letter from the number (see `Docs/BlockCreation.md`).
- The solution comes with the level, so the game does not compute the minimal form: the author knows the solution when writing the level.
- A result variable, as in `1 = ...` (`=` is an alias of ↔) or `... -> 1`, is part of the formula and becomes ordinary blocks: the player may move or remove it like any other block, and each level is shown in the form it was written. Courses write these exercises in different ways; the notation covers the differences in letters and symbols, and the form of each exercise is its author's choice.
- Rejected: propositions written as sentences inside the formula, in brackets, such as `[John eats tofu]` (every repetition retyped the sentence, and long sentences made formulas hard to write and read), or, as alternatives to the brackets, marked by parentheses (which also group) or found by splitting at spaces (which sentences contain); short names instead of numbers, such as `alarm` and `door` (more readable formulas, but the list would need name → sentence pairs); letters given in order of first appearance through a level-wide table, sentence → letter (the number already gives the letter); a fixed frame for the result variable outside the row, `A =` at the start or `→ A` at the end, set by the notation so that each player could pick the form (too much detail for the game's purpose, since the notation already covers the differences in symbols); computing the minimal form in the logic core (a high cost for what the level already brings); `^` for AND in the level texts, as in some courses (`^` is XOR in C++ and C#).
