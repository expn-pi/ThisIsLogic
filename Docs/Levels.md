# Level design

The level format is in Game design, in `CLAUDE.md`. This file holds its details and reasons, and the alternatives rejected.

- Example, a home alarm. Statement: the alarm goes off if the motion, window and door sensors are all on; or if the motion and window sensors are on but the door sensor is off; or if the motion sensor is on but the window sensor is off. Starting formula: `1 = ( 2 AND 3 AND 4 ) OR ( 2 AND 3 AND NOT 4 ) OR ( 2 AND NOT 3 )`. Sentences: "Alarm on", "Motion sensor on", "Window sensor on", "Door sensor on". Solution: `1 = 2`.
- Propositions are numbers in the formulas, and their sentences come in a list. Each sentence is written once, so a typo cannot silently create another proposition; formulas stay short and easy to check, even with long sentences or with statements whose conditions come from context; and, since numbers have no spaces, the analyzer can split a formula at its spaces. The list holds only the sentences, in order, since the position gives the number. Numbers start at 1, as a person counts; the analyzer turns each into an index from 0 (see `Docs/Logic.md`), from which the notation derives the letter (see `Docs/BlockCreation.md`).
- In a formula, the pieces are separated by spaces, and each operator has a single text: the words `TRUE`, `FALSE`, `NOT`, `AND`, `OR`, `XOR`, `NAND`, `NOR`, `THEN` and `IF`, and the symbols `=`, `(` and `)`. Uppercase words give the operators a single rule, with only `=` and the parentheses as symbols, and a formula reads close to its statement; the cost is longer formulas. `IF` is ← because `1 IF 2` says the same as `2 THEN 1`. With a single text per operator, the analyzer is a simple table, and every level is written the same way.
- Level texts are ASCII only. The textbook symbols (∧, ↔...) appear only on the screen, through the notation: in the core's standard C++, a ∧ written in the code depends on how the compiler encodes text, and words are easier to type.
- Splitting at the spaces lets the analyzer read the formula piece by piece instead of character by character. A piece that is neither an operator text nor a proposition number is an error that stops the game: levels are written by their author, so an error is a typo to fix, not a case to handle. A forgotten space, as in `4)`, falls in this case instead of silently becoming proposition 4 without the parenthesis.
- The solution comes with the level, so the game does not compute the minimal form: the author knows the solution when writing the level.
- A result variable, as in `1 = ...` (`=` is the text of ↔) or `... THEN 1`, is part of the formula and becomes ordinary blocks: the player may move or remove it like any other block, and each level is shown in the form it was written. Courses write these exercises in different ways; the notation covers the differences in letters and symbols, and the form of each exercise is its author's choice.
- The levels are written in `Data/Levels.csv`, one per row, and imported as the DataTable `DT_Levels`, whose rows are `FLevelRow`, with one field per part of the level. The file is the source, and `DT_Levels` is reimported after each change; the fields are `VisibleAnywhere`, read-only in the editor, since an edit made there would be lost at the next reimport.
- `Data/` sits at the repository root, outside `Content/`: as with the source files of other imported assets, `Content/` keeps only the imported asset, which remembers its source file for the reimport. The editor does not show `Data/`, so the file is edited outside it (in Rider, in the File System view).
- In the file, the first column is the row name, whatever its header, and the other headers match the fields of `FLevelRow`. A text with commas goes in quotes. `Sentences` uses Unreal's list format, each sentence in quotes: in a spreadsheet, the cell is `("Alarm on","Motion sensor on")`; in the raw file, the cell itself goes in quotes and the inner quotes are doubled: `"(""Alarm on"",""Motion sensor on"")"`.
- Row names describe the level (`Alarm`) instead of numbering it, so they stay valid when the levels are reordered.
- Levels are saved only as their texts. What derives from them, such as the tokens and, later, the logic core's results, is computed by the game when a level is played. With the minimal form out of the game (above), these computations are cheap, and `Levels.csv` stays the only source of each level.
- Rejected: propositions written as sentences inside the formula, in brackets, such as `[John eats tofu]` (every repetition retyped the sentence, and long sentences made formulas hard to write and read), or, as alternatives to the brackets, marked by parentheses (which also group) or found by splitting at spaces (which sentences contain); short names instead of numbers, such as `alarm` and `door` (more readable formulas, but the list would need name → sentence pairs); letters given in order of first appearance through a level-wide table, sentence → letter (the number already gives the letter); numbers from 0 in the level texts (a person counts from 1, and the conversion happens once, in the analyzer); a fixed frame for the result variable outside the row, `A =` at the start or `→ A` at the end, set by the notation so that each player could pick the form (too much detail for the game's purpose, since the notation already covers the differences in symbols); computing the minimal form in the logic core (a high cost for what the level already brings); levels saved precomputed, with the tokens and other data derived from their texts (a second copy of each level, kept in step with `Levels.csv` by a tool to write and maintain, to save computations that are already cheap); `^` for AND in the level texts, as in some courses (`^` is XOR in C++ and C#); the formula as a list of pieces in the file, `("1","=","(",...)` (the import would split it, but every piece needs quotes, doubled in the raw file, which makes formulas hard to write and read); reading the formula character by character (texts such as `NAND` and numbers such as `12` need rules for more than one character); the aliases `&`, `|`, `~` and `->` (a mix of symbols and words, once `NAND`, `NOR` and `XOR` are words); the textbook symbols in the level texts (non-ASCII text in the core's code, and harder to type); more than one text per operator (a larger table, and levels written in different ways).
