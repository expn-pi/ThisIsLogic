# Exercise design

- `AExercise` is the top of the gameplay classes: it loads its level, creates and owns the background target, the formula and the panel, and drives the creation of the blocks from the level's formula and sentences (see `Docs/BlockCreation.md`). `LoadFormula` reads them once: the starting tokens, through `AnalyzeFormula`, its bridge to the logic core, and the sentences. The start of the level, Restart and Undo all create blocks from them, and the starting tokens stay kept for the equivalence indicator. For now the level is the first row of the levels' DataTable (see `Docs/Levels.md`). Later the exercise will own the palette and decide the result. The selection stays in `AFormula`, which keeps what the blocks mean (and later the tree), while `FBlockBoard` keeps the blocks themselves; the exercise learns about the selection's changes and about each change to the blocks through events.
- The exercise keeps a copy of its level's row rather than the pointer that `FindRow` returns: that pointer points into the asset, which the engine may unload once nothing holds it, and the soft reference in the settings does not hold it.
- The selection event carries no data: whoever needs the selection asks the formula, so no copy of it has to be kept in sync. Each change sends one notification, once the state is final (`SelectBlock` unmarks the previous block through `DeselectBlock`, which does not notify). It may also come when nothing changed (tapping the selected block, or the background with nothing selected), which is harmless, since listeners only ask the formula.
- Undo is a command of `AExercise`, like Restart, since rebuilding the blocks takes the factory and the sentences, which the exercise holds. The history lives in `FUndoHistory`, a plain class held as a member, like the factory, which only keeps the snapshots and gives back the previous one (the caretaker of the Memento pattern); the exercise decides when to save (at the start, after Restart and when the formula reports a change) and how to restore (see `Docs/Commands.md`). Like the selection event, the change event carries no data: the exercise asks the formula for the blocks' states.
- The name comes from the exercises of a logic course, which the game imitates: each has a statement, a formula to simplify, tools to work on it and a result.
- Rejected names: `AAdministrator` and `ATeacher` (role names, like `Manager`, fit any task and attract unrelated ones; `Administrator` also reads as system administration); `APuzzle` (generic); `Level` for the field with the level's row (in Unreal, a level is a map, and every actor has a `GetLevel()` that returns its map).
- Rejected: the selection event carrying the selected block (the exercise would keep a copy of the selection); `SelectBlock` calling a notifying `ClearSelection` (switching blocks would send two notifications, the first with nothing selected); Undo as a command of `AFormula` (rebuilding the blocks takes the factory and the sentences, which the exercise holds); the history kept in fields and methods of `AExercise` itself (a class of its own keeps one responsibility, and the exercise only decides when to save and how to restore).
