# Logic core design

The core's rule is in Engineering principles, in `CLAUDE.md`: `Logic/` uses only standard C++, so it can be tested and reused on its own. This file holds the details and reasons, and the alternatives rejected.

- The core reports an error by returning no result (`std::optional`, like a nullable type in C#), and its caller in the gameplay code stops the game with a `check`. The core has no `check`, which belongs to the engine, and the standard `assert` is off in the Development Editor configuration.
- A table of literal data, such as the analyzer's operator texts, pairs each key with its value (`{ "AND", ETokenKind::And }`) instead of using one array per field, as gameplay code does: with no `check`, the core could not confirm that two arrays have the same size, and with pairs there is nothing to confirm.
- The core uses C++20, the default in Unreal 5.8, such as designated initializers (`FToken Token = { .Kind = ETokenKind::And };`, like an object initializer in C#) and `std::map::contains`.
- A token (`FToken`) is plain data: its kind (`ETokenKind`) and, for a proposition, its index in the level's list of sentences, from 0. The kind already tells which operator a token is, so only propositions need the second field. Operators keep the default index, -1, so an index read by mistake from an operator fails loudly at the list of sentences instead of silently giving the first one. One kind per concept; the texts of the levels belong to the analyzer.
- The token has no text: blocks take their texts from the notation and from the sentences (see `Docs/BlockCreation.md`). Besides creating blocks, tokens are how the core will see a formula: the tree (2.2) will be built from tokens, both for the starting formula and for the player's row, which gameplay code will turn into tokens, since the core cannot see the blocks.
- The analyzer (`FFormulaAnalyzer`) turns a level's formula into tokens; in compiler terms, this is lexical analysis. It is a static class, since it has no state and its table is fixed. It is the only place that turns a proposition's number into an index, and it returns no result at the first piece that is neither an operator text nor a number (see `Docs/Levels.md` for the format).
- Rejected: an operator's kind stored as an integer, in the same field as a proposition's index (every use would convert it back, and an integer accepts values that are no kind at all); the token keeping its text, with the number read in its constructor (only the analyzer reads the text, and nothing else needs it); indices from 1 in the token (an offset of one in the notation and at the list of sentences); the analyzer as an object held by `AExercise` (it has no state); `assert` for the errors (off in the project's builds); one method per kind of piece and `std::from_chars` to read numbers (more code than the task needs: a check for digits and `std::stoi` are enough).
