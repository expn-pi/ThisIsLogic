# Block creation design

- Data flow: level texts (DataTable) → analyzer → tokens → factory → blocks → formula, driven by `AExercise`. For now `FFormulaStub` stands in for the level data and the analyzer: it returns the same tokens the analyzer will, and the level's sentences.
- A token (`FToken`, with its `ETokenKind`) is plain C++, no reflection: a kind, its text and, for a proposition, its number, read from the text once, when the token is built. One kind per concept; the aliases of the level texts belong to the analyzer. `FFormulaStub` is temporary: its formula changes freely, and it may be deleted or reused in a test.
- The factory is the only place that knows which block class to create (Simple Factory); `AFormula` knows only `ABlock`. Actors cannot take constructor parameters (the engine calls the default constructor, also for the class default object), so the factory uses a deferred spawn to fill in a block before `OnConstruction`.
- The factory is an object held by `AExercise`, built with the notation's first letter, and it owns the notation, its only user so far. It gives a proposition block the letter of its number and the sentence of that number in the level's list, and an operator block the notation's text for its kind.
- `ABlock` is abstract and asks each subclass for its text (`GetText`): the subclass decides which text and when, and the base knows how to show it (label, width, background and owner notification). `APropositionBlock` keeps its letter and its sentence, set together by `SetProposition`, and whether it is minimized; `AOperatorBlock` keeps its symbol. The level's sentences, with the notation's letters, can also feed a legend like the "Define:" lists of textbook exercises.
- The notation (`FNotation`) holds what the player sees, and the levels never depend on it. The letters are a run of consecutive letters from a given first one: number N gets the Nth, with a `check` that the result is still a letter. Operator texts are kept by kind. For now they are ASCII, since the default font of `UTextRenderComponent` probably holds only Western European characters, and the textbook symbols (∧, ∨, ↔...) would show as squares; they need a distance field font made in the editor with those characters listed in Chars (a forum report says importing a Unicode Range of arrows froze the 5.2 editor).
- The notation lives in `Gameplay/Notation/`, not in `Logic/`: it uses engine types, and the core never needs it, since validity and equivalence do not depend on how a formula is shown. The analyzer has its own notation, the fixed one levels are written in. The name is the logic term for how formulas are written; in Unreal, "Style" names the look of widgets (`FButtonStyle`).
- Shared types are grouped by domain (`Logic/LogicTypes.h`), not by kind of type.
- Rejected: global `Structs`/`Enumerators` files in a `SharedData` folder (unrelated types side by side, included everywhere); a factory holding block classes set in the Details panel (Blueprint subclasses that only held the material; see `Docs/Data.md`); text handling moved down to the subclasses (it would open `Label` and `Background` to them, or duplicate them in each); the base keeping the text, with one method to store it before construction and another to show it later (two paths for the same text); a `SetText` overridden in `APropositionBlock` (it was not virtual, and the name would lie, since the block may show the letter); one appearance method shared by `OnConstruction` and the subclasses that also notifies the owner (during construction the block has no owner yet); separate setters for the letter and the sentence (both always come together, once, at creation, so one method plays the part of the constructor an actor cannot have); a list of letters in each notation (computing them makes a notation just its first letter, at the cost of allowing only runs of consecutive letters); the notation in `AExercise`, which would get the letter or the text before calling the factory (it would repeat the factory's decision of which block gets which); the notation passed to a static factory on every call (it crossed every signature); `T` and `F` for the constants (`T` is also a letter) and `^` for XOR (many read it as AND).
